# UX audit — 2026-09-29

## Player loop

The core loop is strongest when the interface answers three questions in order:

1. What should I do now?
2. What changed because I did it?
3. What can I improve before the next attempt?

The hill, Push control, progress feedback, and improvements list already contain those answers. The main problem was that they competed for attention instead of forming a sequence.

## Findings and changes

### High — The collapsed scroll did not explain its function

The rolled papyrus looked like part of the scenery. Its only visible state was a seal count, while separate dangling tags acted as instant purchase buttons. Players had to infer that the roll opened the upgrade list, and the tags created an accidental-purchase path without context.

**Change:** The collapsed scroll now prints **Improve** directly on the rolled parchment. It shows how many purchases are ready and opens the detailed list. Direct-buy tags were removed.

### High — Opening Improve disrupted spatial continuity

The desktop camera and bottom controls recentered when the scroll opened. This made the hill jump at the same moment the player changed tasks. On phones, the world was reframed below a panel that covered most of the playfield.

**Change:** Improve is now an overlay. The hill and Push control stay in place, so opening and closing the panel does not move the player's target.

### High — The phone layout obscured the game

The open scroll, header, and bottom goal tablet left very little visible playfield. The long physical unrolling animation also made a frequent navigation action feel slow.

**Change:** The phone scroll is bounded by the measured header and controls, uses a short 300 ms unrolling motion, supports swipe-up dismissal, and closes when the player taps outside it.

### Medium — Persistent goals showed too many time horizons

“Now,” “Next,” and “Beyond” appeared together in the most prominent action area. “Beyond” was often unrelated to the immediate attempt, so the footer read as a roadmap when it needed to act as a command surface.

**Change:** The persistent tablet now shows **Now** and one **Next** step. Longer-term progression remains discoverable through the game systems instead of competing with the current action.

### Medium — The improvements panel lacked a stable hierarchy

The heading “Make the next attempt count” described intent but did not name the destination. The dangling purchase tags and long travel time made the physical metaphor harder to understand.

**Change:** The panel has a sticky **Improvements** heading, a contextual “Plan the next attempt” eyebrow, one close action, and a single scrolling surface. The wood rod, rolled parchment, end coils, and physical unrolling motion remain as the signature navigation style.

### Medium — Focus was lost when the panel opened

Keyboard focus could fall back to the page when the scroll changed state.

**Change:** Focus moves to the panel's close button on open and returns to the Improve trigger on close. Escape and controller back behavior remain available.

## Follow-up opportunities

- After the first failed push, present a short result beat that connects the stopping point, earned currency, and newly affordable improvement in one place.
- When an improvement is bought, keep the purchased row in place briefly and update the “Now” instruction before removing or reordering it.
- As later systems appear, group improvements by purpose (reach, production, automation) when the list becomes long enough to require scanning.
- Test first-session comprehension with players who have not seen the design: observe whether they can describe the loop after one attempt without prompting.

## Validation

- Reviewed at desktop and 390 × 844 phone dimensions.
- Verified collapsed, open, outside-click, close, and responsive states.
- `npm run check` passes with no diagnostics.
- `npm run build` completes successfully.
